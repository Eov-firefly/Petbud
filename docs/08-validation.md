# 质量、隐私与发布验证

## 测试层级

1. petcore单元与属性测试：范围不变量、死亡终态、无重复奖励、阶段单调、固定输入重放。
2. 宿主批量仿真：不同照顾人群与种子，输出分布与置信区间。
3. 固件硬件在环：并发、内存、时钟、掉电、存储、升级。
4. 两设备/手机/云契约与事务测试。
5. 真实用户至少四周携带内测；时间加速不替代真实感情与负担观察。

## 关键验收矩阵

| 项目 | 候选门槛/判定 |
|---|---|
| 触摸本地反馈 | 目标p95<150ms，单独测音频/网络高负载 |
| 呼唤反馈 | 检测到有效唤醒后首个微动作目标p95<300ms，不含未验证ASR时延 |
| 动画 | 标准交互场景目标20—30fps，无持续音频爆音 |
| 稳定性 | 72h混合脚本无不可恢复崩溃/存档损坏 |
| 内存 | 最坏场景无OOM；记录峰值、碎片与余量 |
| 续航 | 标准24h使用脚本通过，公布亮屏/语音/联网条件 |
| 近场发现 | 多种携带方式记录召回/误触；验收阈值由现场基线冻结 |
| 同步 | 可重放同seed/config/命令日志，支持断点补传 |
| 赠礼 | 重复、乱序、断电注入无双花；服务端账本守恒 |
| OTA | 每个关键写入点断电后可启动旧或新有效版本 |
| 纪念 | 已死亡不可用旧快照复活；替代蛋一次领取 |
| 隐私 | 未授权账号不可读他宠状态/记忆/路线；日志无密钥/音频泄漏 |

这些是设计目标，不是本次已测结果。供应商噪声、跌落、EMC等门槛在DVT计划结合销售地区细化。

## 成长与概率校准

至少构建正常、每两天互动、过度投喂、过度运动、持续托管、延迟治疗等人群。每批输出pet-years、疾病episodes、死亡原因数、康复时长、发育阶段分布、性格方差、奖励产量。共同随机数用于比较参数，但统计报告记录完整seed范围。

评估死亡的有效暴露量，托管暂停时间不得计入危险暴露。使用二项/Poisson置信区间；零事件约3/N上界仅是近似，不替代完整统计。独立突发与病程死亡总风险都要报告。跨步长比较统计分布，不能把每tick固定概率用于不同步长。

重要性采样仅用于效率：保存似然权重并校验无偏性；强制死亡测试只验证流程，不估计生产风险。先做解析危险率基准，再接复杂病程。

## 死亡启用门槛

- 影子模式与enabled共用相同采样代码，只分离状态提交。
- 产品明确告知，免费治疗/免费新蛋/纪念均可用。
- 正常用户累计风险符合预算，有置信区间而非“没测到”。
- 不能由网络故障、时钟跃迁、更新、会员到期、积分不足触发。
- 严重疾病可理解且有处理窗口，罕见突发明确不伪造因果。
- 用户测试没有未解决的高严重性误导问题。
- 发布决策记录配置哈希与版本；此门槛是开发发布标准，不需要在写设计文档时额外征求授权。

## 隐私与数据

BLE临时标识、可关闭附近发现；实时精确位置不公开；粗地点保存可选；录音默认不留；语音处理、定位、社交分别授权。账户导出/删除有实际流程，不能只有按钮。

设备证书、私钥、支付凭证、云密钥不入仓库。固件生产日志脱敏，调试版与生产版构建分离。对丢失设备支持撤销，旧密钥不能访问新writer。

## 人工内测记录

访谈不只问可不可爱：让用户描述“它有什么习惯”“今天为何主动拿起它”“哪里像被催任务”“是否愿意带出门”。单机无朋友用户单独统计，避免只在开发团队互相碰设备时证明社交成立。

## 本次文档验证范围

仓库提供JSON/链接/约束校验工具；没有固件、App、后端实现与实机测试结果。未来实现必须独立建立CI，不将本次文档校验当作产品测试通过。
