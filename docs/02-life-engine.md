# 概率生命与成长引擎

这是产品核心。状态边界是确定的；动作、偏好形成、生长扰动、疾病和结局是有条件的概率过程。不得用“按按钮固定播放动画”替代本章。

## 1. 状态及时间

所有归一化变量范围 [0,1]，单位见字段。不同物种使用独立参数表。

| 层 | 字段 | 定义 |
|---|---|---|
| 身份 | pet_id、species、genotype、born_at | 出生后不可重抽，genotype 为虚构数字遗传参数 |
| 先天 | adult_size、metabolism、constitution、temperament | 有界分布，避免极端弱体质；付费不改变体质分布 |
| 生理 | satiety、hydration、energy、sleep_debt、hygiene、health | 连续值；正负方向显式命名 |
| 发育 | bio_age_s、development、mass_ratio、coat_stage、coordination | 生物年龄不是积分等级 |
| 心理 | valence、arousal、security、attachment | 短期情绪和长期关系分别更新 |
| 偏好 | toy_preferences、routine_confidence、social_bonds | 带证据数量、衰减率，不由一次互动决定 |
| 病程 | disease_id、severity、onset_at、treatment、recovery | 同时首版最多一个主病程，避免叠加失控 |
| 生命 | alive / ill / critical / recovering / deceased | deceased 为终态，不可因重新同步复活 |

使用单调时钟推进运行时间；UTC 只用于展示和可信时间锚。更改时区不改变年龄。重启后依据最近可信时间补算；无可信时钟时暂缓危险补算，等待手机校时，不将异常时间差视作疏于照顾。

默认固定生理步长 60 秒，行为在事件/动作结束时评估（非每帧），动画 20—30 fps，物理固定 30 Hz。所有候选频率要实测。年龄以真实经过时间为基准，发育由营养、休息与健康作有界调节。

## 2. 生理推进

每步按 dt 以秒为单位更新，参数单位不可混用：

```
satiety -= basal_food_per_s * metabolism * activity_factor * dt
hydration -= water_per_s * activity_factor * dt
energy += (sleeping ? recovery_per_s : -activity_cost_per_s) * dt
sleep_debt += (awake ? debt_per_s : -repayment_per_s) * dt
hygiene -= dirt_per_s * environment_factor * dt
```

进食即时增加饱腹，但营养由消化队列平缓吸收。过量不提供额外奖励，长期过量可能改变体态和不适风险。单次漏喂不会造成永久发育损失；所有变量 clamp，更新后检查 NaN、溢出、非法状态。

健康主要跟随病程及长期状态变化，不因随机日常动作直接扣除。体力低不能无条件映射为疾病。舒适、饮水、休息、护理各有可解释效果。

## 3. 发育模型

候选阶段：0—3天初生、3—14天幼年、14—35天少年、35—46天向成年过渡、46天后成年。临界值采用秒精确定义，UI 可用自然日措辞。

```
development += base_rate(stage) * clamp(nutrition * rest * health_factor, 0.65, 1.15) * dt
size_target = species_curve(development) * genetic_adult_size
size += (size_target - size) * smoothing(dt)
```

发育增长单调；暂时生病可放慢但不返老还童。体重与骨架分开，体重可增减。健康恢复后有上限的追赶发育，避免永久惩罚。毛发用物种/品种阶段插值与贴图变化；乌龟不长毛。

每个体出生采样固定曲线差异；每日增长噪声采用平滑、均值回归、有上下界过程，不能逐帧抖体型。动作协调性由年龄和适度练习共同增长；重复练习收益递减。

## 4. 行为：带上下文的随机策略

行为选择分四层：可行性筛选 → 计算效用 → 概率采样 → 持续执行。安全/生命终态/治疗动作优先级独立，不交给随机选择。

每个动作 a：

```
score[a] = base[a] + W[a]·needs + T[a]·traits + C[a]·context
           + preference[a] + familiarity[a] - fatigue[a] - repeat_penalty[a]
p[a] = exp((score[a] - max_score)/temperature) / sum(exp(...))
```

动作定义包含物种、发育阶段、进入/退出条件、最短时长、冷却、可中断点、资源消耗、动画标签。先过滤不可执行动作再 softmax，至少有安全 idle；temperature 有界且随情境变化，病重不能采样高速追球。

普通状态同一次刺激至少保留多种非零合理反应；禁止极小概率不合理动作“为了随机而随机”。加入最近动作衰减、短期意图与持续性，避免每秒换主意；不强制轮流播完动作。

示例：清醒、健康、熟悉主人时呼唤昵称：跑来 0.55、歪头后靠近 0.25、先伸懒腰 0.15、远处轻叫 0.05。疲劳时改用另一组上下文权重。数字是效果演示，不是最终硬编码概率。重复呼喊触发冷却，不能持续强迫跑圈。

## 5. 学习与记忆

偏好以先天先验加观察更新：成功互动提升对应玩具证据；中性事件影响小，拒绝要区分疲劳和真正不喜欢。习惯按时段反复共现形成，证据不足只标“可能”。一次漏陪不消除长期信任。

关系参数缓慢更新，使用每日变化上限。友好互动改变对特定朋友的熟悉度；陌生人的负面事件不能直接降低对主人的信任。按物种定义亲近动作，龟的信任可体现为主动靠近和不再躲藏。

## 6. 事件危险率，避免 tick 累积错误

疾病、恢复、恶化、突发死亡均以时间危险率建模：

```
p(dt) = 1 - exp(-lambda(context) * dt)
# lambda 单位 /秒；若配置用 /小时，执行前除以 3600
```

小 dt 可用 `-expm1(-lambda*dt)` 保精度。采用固定生理步长保证重放；不能根据 fps 调概率。步长等价测试比较统计分布而非要求不同步长随机序列完全相同。

病程为半马尔可夫过程：healthy → discomfort → ill → recovering；ill 可能 → critical；critical 可能恢复、恶化或死亡。最小驻留时间、暴露窗口和康复免疫窗口防止瞬间连跳。首发病种可用虚构名称：消化不适、疲劳综合征、清洁相关不适；不作为真实动物医疗建议。

风险因子使用有界加权后映射，限制总倍率。良好护理明显降低恶化危险率、提高恢复危险率，但非百分百成功。全部病程可正常免费治疗；积分不足不阻断救治。

## 7. 极低概率死亡与发布策略

正式产品支持永久离世，死亡后新 pet_id 重新开始。三类原因分别记录：严重疾病、极罕见突发、未来自然衰老。v0.1 不启用强制寿命；老化模型留扩展口。

正常照顾候选总体风险预算：一年不超过约 0.2%，其中健康突发预算约 0.02%/年；这是待验证设计目标，不是已证明或对用户保证。疾病死亡也必须计入总体预算，不能只限制突发概率。

仅将 0.02% 年度突发概率换算为常危险率示例：

```
lambda_per_hour = -ln(1 - 0.0002) / (365 * 24)
```

健康突发不因付费改变，也不能伪造事前征兆。允许的死亡上下文限定为“正常模拟时间且未处托管/时间异常/存档修复”。疾病严重阶段候选至少 24 个现实小时的处理窗口，睡眠静音期不要求值守；具体病程需统计校准。

实现 `mortality_mode = shadow | enabled`：shadow 仍产生审计候选，不改变 alive；开发/封闭初测默认 shadow。发布 enabled 的条件见质量文档。影子测试不代表正式取消死亡，也不能宣称生产风险已验证。

一次死亡原子写入终态、death_event、纪念快照；重启不重复死亡动画或领取蛋。硬件丢失、损坏、OTA 错误、存档 CRC 错误不生成死亡事件。死亡状态恢复以已确认事件序列为准，不能用旧快照覆盖。

## 8. 离线与托管

离线网络不等于无人照顾。候选 12 小时无有效互动后自主模式，24 小时后托管；用户可提前开启。托管维持基本状态，年龄可继续、发育减速、奖励暂停、死亡危险推进暂停，UI 明示。既有严重疾病进入托管时免费自动基础护理，不用托管制造刷奖励路径。

恢复补算最多按分钟步推进前 24 小时，其余按托管汇总，计算预算不足分批处理；不得用大 dt 一次抽取多个互斥终态。断电不可准确还原时按保守托管，不补死亡。改变系统时间无额外积分或成长跳跃。

## 9. 随机性与可重放

采用版本化 PCG32 等确定性 PRNG，明确算法、字节序、seed/stream，使用无偏采样。行为、成长、疾病、死亡分别独立 stream，增加动画不能改变死亡结果。种子在首次领养生成并持久化，普通 UI 不暴露；权威在线交易使用独立服务端安全随机数。

所有命令有 command_id、seq、logical_time；同 seed、配置版本、输入序列、core 版本产生相同结果。跨平台 core 避免未定义浮点差异；v0.1 规定定点状态和定点概率表，宿主机浮点公式用于校准后生成表，不能直接声称跨架构浮点逐位一致。

快照包括 PRNG 状态与 stream counter；事件附原因码、关键输入及配置哈希。日志有界，不永久存原始音频或连续轨迹。用户界面显示可理解原因，不展示内部风险精确小数。

## 10. 测试情景

正常、低频、过度喂食、过度运动、频繁呼唤、长期离线、断电恢复、疾病治疗/延迟治疗、重复启动、时间回拨、同一品种不同种子。比较阶段时间、性格方差、疾病和康复分布、年累计死亡、积分产量。

极稀有死亡用解析危险率、强制边界测试和加速/重要性采样验证代码；风险估计需真实权重与置信区间。零死亡不证明零风险；零事件上界可参考约 3/暴露量。不得用提高危险率的演示结果直接宣称实际年死亡率。
