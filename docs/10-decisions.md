# 决策、假设、开放问题与资料

记录日期2026-11-04（用户时区Asia/Shanghai）。版本v0.1为开发基线，不代表所有参数已通过评审。

## 用户已明确的方向

品牌宠芽Petbud；屏幕主导；评估两只可动耳；三颗魔法蛋、狗猫龟、会员专属种类；破壳、命名、由小长大；喂食、晒太阳、玩耍、清理、治疗；积分换窝和玩具；角度力度扔球；呼唤名字回应；GPS相关散步；近场招呼、交友、赠礼与共同记忆；行为与成长均具有概率；极低概率永久死亡，重新领蛋。

## 本方案作出的实现决策

| 决策 | 理由 | 复核点 |
|---|---|---|
| 手机辅助定位作为首版 | 降低功耗/体积，优先验证散步 | 是否必须脱离手机远程定位 |
| 动耳并行PoC | 情感收益与结构代价需比较 | EVT前定主SKU |
| 可移植本地core | 离线响应、仿真和故障可复现 | 屏+语音并发资源 |
| 上下文概率策略 | 既有变化又保持性格 | 用户能否辨识差异 |
| 危险率而非每帧随机 | 控制长期累计风险 | 人群仿真区间 |
| 死亡先影子后正式启用 | 保留用户要求，避免未校准直接伤害体验 | 发布门槛完成 |
| 在线结算赠礼 | 首版明确解决断网双花 | 后续是否需要离线可信钱包 |
| 会员不影响生存率 | 关系和公平体验 | 支付方案冻结 |
| 一设备一活宠 | 降低复杂度、保持陪伴焦点 | 多宠产品需求 |

## 尚需决策，不阻塞宿主核心开发

1. 目标售价、销量级别、首发地区及是否成人限定。
2. 屏幕尺寸/外壳形态、挂包和桌面优先级。
3. 动耳是否加入主SKU、独立GNSS/蜂窝是否必须首发。
4. 美术风格：像素、手绘或柔和2.5D；不能到量产前才定。
5. 成年持续多久、是否未来自然老死；当前不设强制寿命。
6. 自定义名字免按键唤醒的成功标准和成本。
7. 正式死亡风险预算；当前数字仅候选，用户要求“极低概率”是确定需求。
8. 会员内容、价格、支付渠道与权益保留条款。
9. 商标、域名、参考硬件/素材/代码授权。
