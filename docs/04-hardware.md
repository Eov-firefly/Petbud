# 硬件与结构方案

## 基线与选型边界

首版屏幕主导，开发板验证后定 PCB。候选 ESP32-S3 模组，8MB PSRAM、16MB Flash 作为资源预算起点，不是已定料号；采购前核对具体模组组合、供货、射频和法规。芯片功能依据[官方产品页](https://www.espressif.com/en/products/socs/esp32-s3)，本项目并未实测并发负载。

| 子系统 | 候选 | 选择/验证标准 |
|---|---|---|
| 主控 | ESP32-S3 带 PSRAM 模组 | 显示+音频+BLE并发的CPU、内存、延迟 |
| 显示 | 2—2.8英寸 IPS，SPI RGB565 | 优先320×240级，户外可读、刷新与成本 |
| 输入 | 电容触摸、实体键、顶部触摸 | 戴手套/包内误触/湿手条件验证 |
| 音频 | I2S MEMS麦克风、I2S功放、扬声器 | 回声、机壳共振、可懂度、静态电流 |
| 运动 | 带 FIFO/运动中断的低功耗IMU | 步行与车辆颠簸区分；必要时仅三轴加速度 |
| 光照 | I2C环境光 | 不作紫外线或温度计 |
| 电源 | 锂电、保护、充电管理、负载分配、测电量 | 边充边用温升、低电压关机、峰值电流 |
| 接口 | USB-C USB2/供电、调试焊盘 | CC配置、ESD、烧录与工厂测试 |
| 扩展 | 动耳电源开关/PWM/电流保护 | 机械堵转不能拖垮系统 |

选触摸SPI屏可减少并行RGB占用；最终引脚表在器件锁定后编制，不凭芯片名称猜 GPIO。须检查启动绑带、USB、PSRAM占用、DMA与I2S资源。

## 资源及存储预算

320×240 RGB565单帧153600字节；双缓冲约300KiB。仅示例：一个24帧全屏未压缩动画约3.69MB，三物种多阶段不可简单全帧堆满Flash。用角色局部帧、图集、背景复用、增量/轻量压缩；比较解码CPU与总线吞吐。

16MB Flash候选布局预算：系统/NVS/OTA元数据约0.5MB，两应用槽各约3MB，剩余约9.5MB用于资源与日志。实际ESP-IDF编译后重新排布并留余量；语音模型和完整美术可能超预算，需增加存储或裁剪，不能承诺此布局装下全部内容。资源分包、签名manifest、版本兼容及恢复包见固件文档。

## 功耗预算方法

先定义使用场景，再选电池。候选容量800—1200mAh仅用于样机体积评估。

例：睡眠18h×3mA + 环境待机4h×15mA + 亮屏1.5h×120mA + 音频/网络0.5h×200mA = 394mAh/天。容量折损及转换损耗按综合可用80%时，1000mAh约2天；这只是算例，不是实测续航。场景必须互斥，总时长24h。常开唤醒可能显著提高底电流，需另算，不能把深睡和持续监听同时假定成立。

定义四档：深睡（无常开监听）、感知待机、交互、联网；IMU中断唤醒，BLE窗口化扫描，Wi-Fi按需。每档实测平均/峰值与转场耗电，最后以一整天标准脚本验证。低电量先关动耳、限制联网，保存状态后安全关机。

## 耳朵评估

A纯屏、B固定软耳、C单电机联动耳三组比较：情感感知、愿付价格、重量、噪声、续航、跌落损坏率。C需有机械限位、柔性件、堵转保护、可维修连接。不同物种采用中性硬件耳或可换壳，避免龟显示配猫耳成为默认违和。

未通过可靠性/功耗门槛，首发不装动耳，但保留主板扩展接口是否占空间由EVT决策。不可用连续舵机保持力维持静态姿态。

## 定位与独立版本

V1手机GNSS/系统定位 + 设备BLE，不需本体GPS。手机不在附近仍记录运动但无路线；App后台行为必须实测iOS/Android限制，不能保证永远扫描或定位。

V2可加独立GNSS；只能获得坐标，远程上报另需蜂窝/其他通信、天线、资费和认证。GNSS不是两宠近距测量；本体定位版作为单独成本/体积评估，不伪装基础功能已实现。UWB仅在确需准确测距且双方硬件支持时评估。

## 结构及制造

尺寸目标先控制掌心/包挂舒适度，最终以屏、电池、扬声器和天线堆叠确定。挂点承担整机载荷，避免可脱耳朵当挂点；电池不受螺钉挤压；射频净空远离金属与电机。防汗、可擦拭、散热与扬声孔平衡，未测试不标防水等级。

EVT输出原理图、PCB、BOM、功耗/音频/射频报告；DVT输出跌落、寿命、温升、充电与ESD报告；PVT输出烧录、密钥注入、校准、序列号、工厂测试和良率。认证范围按销售地区确认，不编造已认证结论。
