# 宠芽浏览器模拟器 Alpha 0.4

一个可本机运行、无构建依赖的独立实现的软件原型（社区形象来源见素材说明）。无需芯片、API Key或账户。用于验证交互和概率行为，不是ESP32指令集、功耗或硬件外设仿真。

## 本机启动

安装Python 3后，在仓库根目录运行：

```bash
cd simulator
python3 -m http.server 8080 --bind 127.0.0.1
```

Windows可把`python3`换成`py`。打开 **http://localhost:8080**。按 Ctrl+C 停止服务。不要直接双击index.html，ES模块需要HTTP服务。

若没有仓库，先：

```bash
git clone https://github.com/Eov-firefly/Petbud.git
cd Petbud/simulator
python3 -m http.server 8080 --bind 127.0.0.1
```

端口被占用可改8081，访问地址同步修改。Chrome/Edge/Firefox等现代浏览器支持Canvas、ES模块、dialog与localStorage。语音识别能力随浏览器而异，localhost为开发测试入口；按钮呼唤始终可用。

## 推荐体验路径

1. 选择猫、狗或龟的一颗蛋，破壳后起名。
2. 喂饭、摸摸，间隔几秒反复按设备心形键，观察不同回应。
3. 按住屏幕右下的小球，向希望投出的方向拖动后松开。猫狗会追/观察/扑，龟慢慢靠近。
4. 点“去散步”“遇见糯米”“送小叶子”，查看回忆。
5. 在成长实验室选择加速或“+1天”，观察体型及阶段；恢复实时不会丢失成长。
6. 模拟不适、免费护理、托管；离世演示要在折叠菜单内二次确认。
7. 刷新页面验证存档；导出JSON可留备份，导入会替换当前活宠。

## 已实现

- Codex Pets社区猫狗龟11组逐帧动画、原创房间、球物理与动作序列；鼠标/触摸输入，基本移动端布局。
- 先天气质、上下文加权随机动作、行为/成长/疾病/死亡独立xorshift32流。
- 饱腹、体力、清洁、健康、亲密、陪伴星、窝、阶段和体型变化。
- 简化疾病、护理、极低概率死亡；默认影子模式，启用死亡有显式确认。
- 模拟朋友重逢、赠叶和共同回忆；无真人社交/库存交易。
- 本地自动保存、导入导出、暂停、加速、长期离线保护性托管。
- 首触解锁声音、录制猫狗叫声、按动作变化的音色/节奏，以及程序合成呼噜和动作音；可选浏览器语音识别。语音识别可能由浏览器服务联网处理；非离线唤醒或声纹识别。

## 与正式技术规格的差异

本原型用JavaScript和简化小时积分，不是最终C++petcore；使用xorshift32而非拟定的PCG32，浮点不保证跨架构逐位重放。相同JS引擎/seed/输入可重放，动画帧率影响输入步长，因此当前没有固定tick的硬件级确定性承诺。生理和危险率尚未校准。

未实现：真实GPS/BLE、账户与云备份、双真实设备社交、可转移库存、支付/会员、真实LLM、毛发分层、完整长期习惯学习、真实发育曲线与硬件固件。当前习惯计数只影响玩球选择，不能宣传成已经实现长期人格学习。

正常离线补算前12小时简单推进，之后保护性托管，最长补算一年；实际在线加速时不会自动托管，方便观察状态。永久死亡模式下不能用旧快照覆盖的云端权威约束尚未实现，本地可导入旧档，不能用作商业防作弊系统。

存档属于当前浏览器/端口，不同浏览器或端口不共用；清理浏览器数据可能丢失，请主动导出。只读纪念最多保留最近10只，并随JSON导出；当前回忆面板展示当前宠物，历史完整记录可在导出文件查看。原型无秘密和服务凭据，不公开网络端口。

## 测试

Node.js 20+：

```bash
cd simulator
npm test
```

无npm安装依赖。可选页面集成测试：安装Playwright、准备Chromium、先启动HTTP服务器，再运行`node tests/browser.cjs`。测试使用`PETBUD_CHROMIUM`指定浏览器路径、`PETBUD_URL`指定地址；默认路径适合Linux开发环境。截图写入`PETBUD_ARTIFACTS`目录（默认系统临时目录），不属于源码。

## 后续迁移

先冻结输入/状态/事件Schema和固定tick语义，将core.js替换为C++核心的WASM构建或同源绑定；再做ESP-IDF适配。保持UI与核心分离，浏览器作为调试前端和回归测试入口，不直接重写为另一套硬件规则。

HachimoDock只作为外观与技术选型参考，未复制其素材；猫狗龟图集使用Codex Pets社区公开下载素材，见[素材来源与使用边界](assets/NOTICE.md)，商业化前需确认相应形象授权。

## Alpha 0.2 触屏与素材更新

日常操作全部在设备屏幕内完成：底栏「喂饭、陪玩、呼唤、出门、照顾」；点击饭碗喂食、睡垫/窝睡觉、宠物抚摸。齿轮菜单可改名、语音、静音、导出。照顾菜单一层展开即到清理、晒太阳、睡觉、护理、换窝和托管。设备外保留状态/回忆与开发实验室，不作为日常操作前置。

动画图集状态：待机、左右奔跑、抬爪、跳跃、低落、等待观察、忙碌动作、低头查看、左右环顾。Petbud按情境组合为观察→招呼→靠近等序列。睡眠、进食等部分动作复用接近的原帧并加入场景表达，尚非专门拍摄的完整喂食/睡姿动画；毛发成长仍待自有分阶段素材。

默认声音开启，但浏览器必须在第一次触摸后才允许发声。顶栏和设备屏幕内均可静音；静音立即停止播放。猫狗使用本地OGG录音，乌龟以动作音反馈，声音不依赖联网服务。支持现代Chrome/Edge；语音识别仍是独立的可选浏览器能力。

新增触屏集成检查：启动服务器后运行 `node tests/touch-browser.cjs`（需Playwright和Chromium）。它检查图集加载、录音解码后的声音事件、静音、触屏菜单和存档。自动检查不能代替真人听感评估。

## Alpha 0.3 自然动作与幼猫音效

新增独立动画时钟，动作从开头开始播放；静止观察有停顿，短动作只播放一次，站姿切换短暂过渡。位置更新采用限加速度的移动，到达后停稳；步态按实际移动距离推进，静止时不原地奔跑，不再将所有动作强制滑回场景中心。龟具有独立较慢速度。睡姿不再压扁图片。

猫叫替换为两段CC0幼猫风格音效（来源标明AI生成，非现场录音），呼唤与相遇使用不同片段，保持原速；抚摸以呼噜回应，增加猫叫间隔避免叠音。来源与处理见[素材说明](assets/NOTICE.md)。原图集帧数、可用姿态仍有限，尚非逐帧手工制作的完整真实动作库。

增加移动速度、停步、站姿不漂移、龟速度和动画局部时钟的回归测试。HachimoDock默认狗未合入，理由是其当前许可对独立产品复用有单独约束。

## Alpha 0.4 连续视频与实时互动

默认小狗采用HachimoDock西高地连续视频参考演示，共9段、3146个源帧、854×480/24fps；猫、龟保留图集，不冒称已升级。此更新按用户指定素材用于非商业效果评估，原文件、来源和许可证见[影像包说明](assets/cinema/README.md)。旧章节“未复制HachimoDock素材”描述的是0.1—0.3状态，不适用于本版本的参考演示包。

选狗后，生活片段原生视频播放；按喂食、抚摸、呼唤等切换完整动作，切换时过渡并等待下一视频可解码，避免空白。玩球和散步进入同一只白狗的实时合成场景，位置由运动控制器驱动；原视频内部步态并不完全受控，尚不能保证任意路径都达到专业动画的脚底锁定效果。开发实验室可选择旧图集作对照。

保留本地幼猫音效和原有存档。暂停会停止视频时间；生活片段不随模拟成长速度加速。未就绪或失败时明确提示，不能静默冒充连续视频播放成功。

运行 `python3 tools/inspect_media.py assets/cinema` 检查资源，`node tests/cinema-browser.cjs` 检查实际视频解码、媒体时间推进、暂停与模式切换；仍需真人评估主观效果及目标设备解码性能。
