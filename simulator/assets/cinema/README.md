# 连续影像演示包

本目录用于用户明确要求的非商业素材效果评估，展示连续视频与实时交互的组合方式。9段MP4来自YizhengWw/HachimoDock默认西高地小狗，保留原始文件，无重新生成、插帧或升帧；出处、时长和原始帧数见manifest.json，原许可证完整保存在[HACHIMODOCK-LICENSE.md](HACHIMODOCK-LICENSE.md)。版权归原权利人，不暗示合作或背书，不将本演示称为自有或已获得独立产品商用授权的资产。

当前许可证除非商业条款外也包含独立产品复用限制。本演示与可商用正式素材分开；正式产品资产应替换为自有素材或取得相应书面授权，保留许可文件不等于额外授权。

## 实际资源

854×480、24fps的原始视频，9段共3146帧，文件合计约4.29MB（精确值运行检查脚本）。idle和walk可循环，其他完整片段播放后返回idle，用户明确操作可以切换。片段间短暂交叉过渡，未使用“复制几张图片就声称生成数百帧”的方法。

这是预制动作，不是实时生成解剖动作或3D模拟。原素材有道具、镜头内位置变化、生成视频本身可能存在的瑕疵；睡眠使用安静等待片段，没有独立闭眼睡眠素材；出生与成年暂复用同一外观。猫和龟尚未制作对应连续动作库。

## 两条渲染路径

- 生活片段：浏览器原生H.264解码，以完整视频展示细节，独立于养成加速时间。
- 实时互动：CPU画布以24fps上限生成边界连通的背景蒙版，保留内部眼鼻区域；做边缘软化后与场景合成，位置由Locomotion控制。此方法适合当前近黑背景的白狗，不是通用抠像模型。复杂背景、黑色宠物及低端设备需改用离线透明WebM/序列图。

不能保证黑边、毛发边缘或原视频内部位移完全消除。后续自有素材应输出透明背景、固定根节点/脚底、原地步态，并加入明确进出动作与循环点。

## 替换素材与移植

manifest逐段声明路径、编码、尺寸、帧数、fps、时长、来源与循环属性。自有新动作沿用idle/eat/play/walk/call/touch/look/happy/rest这些语义ID即可接到播放器；保留一致角色、机位、光照、尺度和脚底基准。新增ID同时调整cinema.js的映射。

在simulator目录运行：

```bash
python3 tools/inspect_media.py assets/cinema
```

浏览器直接播放原MP4。实机P4另做640×480/15fps的H.264 Annex-B转码与实际解码测量；不要把浏览器成功当作P4性能已经验证。片段、语义映射、养成状态和音频事件分离，便于替换资源和移植。
